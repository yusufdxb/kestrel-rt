# Design decisions

Each decision below names the failure mode it addresses and the measurement that backs it. Numbers are from
the physical RA4M1 (docs/BENCHMARKS.md, docs/TEST_PLAN.md, docs/PHASE2_RESULTS.md).

| Decision | Failure mode it addresses | Evidence on this board | Cost accepted |
|---|---|---|---|
| **Static allocation only** (no heap; the image gate rejects `malloc`/`_sbrk`) | allocation failure or fragmentation appearing hours into a run, where no test window catches it | every buffer, stack and queue is fixed at link time (benchmark image 20,569 B RAM); 10.4M-period Phase 1 soak and 10.0M-period Phase 2 soak with 0 faults | the task set and queue depths are compile-time decisions |
| **Fixed-priority preemptive scheduling, unique priorities** | a long background job delaying a control release (the superloop's failure) | superloop control misses 41% of jobs at 5.5x load, Kestrel 0; response-time analysis predicted the order in which tasks fail on hardware (health, comms, sensor, safety) and never called a failing load schedulable | priorities are a design-time contract; RTA was 0.25 to 0.75 of a load step conservative |
| **Skip-release overrun policy** (a release that finds the previous job running is skipped and counted) | catch-up bursts: back-to-back late releases that let one overrunning task starve everything below it | 7x overload: Kestrel runs control at half rate while safety, sensor and comms miss nothing; FreeRTOS with the default `vTaskDelayUntil` pattern misses every control job and runs no other task | the late task loses releases instead of catching up |
| **PendSV for every switch** (lowest exception priority, tail-chained) | switching inside a nested interrupt, where a partial register save or an ISR delayed by a switch breaks timing | PendSV body p50 316 / max 654 cycles; signal-to-wake p50 13.0 us with the MPU on | ~2.7 us slower per signal-to-wake than FreeRTOS notifications (kernel accounting, MPU retarget) |
| **Kernel timer ISR at the highest device priority** | release latency depending on whatever device interrupt is running | timer compare-to-handler p50 1.75 us, max 4.2 us; 0 misses under a 300 kHz interrupt storm at priority 3 | it can land inside a context switch: 0.1% switch tail up to ~40 us, found with the flight recorder |
| **Bounded IPC with explicit full policies** (SPSC: reject + counter; mailbox: overwrite latest with a sequence; trace rings: drop newest + counter) | a producer blocking on a full queue, or silent data loss | host tests prove order, reject counting and index wrap across 2^32; on hardware, every dropped record is counted and equals the host's gap count (10,380 in the TX-stall test) | consumers must check sequence numbers for staleness |
| **Immediate priority-ceiling mutex** | unbounded priority inversion | plain mutex: high-priority task blocked 5,173 us (the whole medium-priority burst); ceiling: 909 us (only the low task's critical section) | a holder delays intermediate tasks even without contention |
| **DMA for all UART traffic** (TX and RX, repeat-mode ring) | per-byte interrupts losing characters when a higher-priority ISR runs longer than one character time | fault runs 2 and 3 each lost one injection command to SCI9 receive overruns; with DMA RX: 300/300 commands acknowledged, 0 receive errors, fault campaign 17/17 | ring sizing and overrun accounting from DMA counters instead of simple ISR code |
| **Watchdog voting** (critical tasks vote; one supervisor feeds the WDT; noncritical stalls only degrade) | a watchdog that is fed by a healthy low-priority loop while control is hung, or one that resets the board for a stuck logger | control or sensor hang: supervisor stall record, WDT reset, recovery 1.00 s; comms, health or logger hang: degraded flag only, 0 critical misses, no reset | a debugger halt counts as a stall; all diagnostics use non-halting SWD reads |
| **MPU: unprivileged tasks, per-task stack region + 32 B guard, kernel data private, NULL page trap, SRAM execute-never** | a task bug corrupting kernel state or another task's stack, going undetected | fault campaign: write into kernel `.bss` trapped (MMFAR 0x20000898), stack overflow caught in the guard, SRAM execution trapped, NULL accesses trapped; contained faults caused 0 control misses | ~0.3 us per switch pair; the kernel footprint (12,291 B flash) is larger than FreeRTOS's in this configuration |
| **Crash capture into VBATT backup registers, persisted outside the handler for contained faults** | losing the cause of a reset; delaying control while writing it | records survive resets and are read after reboot with the right class; the first version wrote the record inside the handler (~9 us per byte, 1.1 ms per record) and caused a control miss, so contained faults are now persisted by the comms task | capture 38 to 45 us before the backup-register write |
| **Drop-over-block telemetry** | a stalled host or USB bridge back-pressuring the control loop | 5 s on-target TX stall: 0 critical misses, p99 unchanged; host stopped reading for 16.9 s: 0 misses on every task | telemetry has gaps under stalls (counted) |
| **Binary tracing** (8-byte events, 12-byte per-job records, armed/triggered capture) | timing bugs that printf-style logging hides or causes | found the in-handler crash-record write that caused a control miss, and attributed the context-switch tail to the timer ISR | host-side decoder needed to read anything |
| **Phase 2: bounded communications budget** (link task at priority 4, per job <= 512 B, <= 16 frames, 300 us, RX time checked every 16 bytes) | a flooding or misbehaving network processor consuming RA4 CPU above the critical tasks | the first budget, checked only between 64-byte chunks, let a job reach 507 us (gate G6 failed); after the fix the worst job was 314 us, and a synthetic 300 us job every 5 ms (N4) left control p99 at 47.88 us | excess ESP frames are dropped at the ring and counted; the ESP gets no back-pressure beyond the acknowledged sequence |
| **Phase 2: DMA ring + receive-error storm guard** | per-event CPU load the ESP can cause with a broken line | ESP download mode (TX held low) produced ~1.17 million error interrupts before the guard; with the guard a 15 s break gives 19,200 errors and 600 mutes, 0 misses | up to 20 ms of receive muted after 32 errors |
| **Phase 2: sessions, sequence window, replay list, token bucket (400 frames/s)** | stale or replayed frames after an ESP reboot changing RA4 state; floods reaching the parser at line rate | 32/32 stale frames rejected after a reboot; 15,000 malformed frames, 0 accepted; 83,711-frame flood: 8,526 rate-limited, all accounted | at most 400 accepted frames/s by policy |
