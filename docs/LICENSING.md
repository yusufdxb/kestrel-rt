# Licensing

## Arrangement

- **Kestrel-RT original code: MIT** (LICENSE). This covers the RA4M1 runtime (startup, kernel, safety,
  trace, drivers, link, apps, linker script), the baselines' shared shim and configurations, the host tools,
  scripts, tests, docs and figures, and the Kestrel-authored ESP32-S3 files `esp/KestrelBridge/kx_node.{h,cpp}`,
  `esp/build.sh` and the Kestrel lines in `esp/patches/KestrelBridge.ino.ed`.
- **Vendored CMSIS headers: Apache-2.0**, unmodified, headers retained, license text in `LICENSES/Apache-2.0.txt`.
  MIT and Apache-2.0 coexist here without conflict: the headers keep their own license, nothing Apache-licensed
  is relicensed.
- Everything else (FreeRTOS, Zephyr, the Arduino bridge, arduino-esp32, ESP-IDF, toolchains) is fetched or
  installed by the user and is not part of this repository. Inventory: [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

MIT was chosen because it is the conventional permissive license for embedded portfolio and library code,
it was already the project license, and no redistributed dependency constrains it.

## The ESP32-S3 bridge fork (the one open question)

The Phase 2 ESP32-S3 firmware is a fork of Arduino's official UNO R4 WiFi USB bridge, tag 0.5.2
(`github.com/arduino/uno-r4-wifi-usb-bridge`, commit `4394ba03c6bd1afb661da2944de68359ec5b415a`).

What was checked (2026-09-30):
- the repository at that commit has **no LICENSE/COPYING file**, and GitHub reports no license for it;
- `UNOR4USBBridge/UNOR4USBBridge.ino`, the file the fork modifies, has **no copyright or license header**;
- some other files in that tree carry their own headers (for example `freedap.c/.h`: BSD-3-Clause, Alex
  Taradov), but the sketch itself does not.

Without a license grant, the default is that the upstream sketch is not licensed for redistribution. This
repository therefore does **not** redistribute it or a modified copy of it. Instead:

1. `esp/patches/KestrelBridge.ino.ed` is an `ed` script generated by `diff -e`. It contains only line
   addresses and the lines Kestrel writes; it does not reproduce the deleted or retained upstream code.
2. `esp/build.sh` takes a user-supplied upstream checkout (`KX_BRIDGE_REF`), checks the upstream sketch's
   sha256 (`13dbc655...a854`), applies the script, checks the result's sha256 (`effcb679...194e`, the
   exact sketch that was validated on hardware), and stages it with the unmodified upstream files and
   Kestrel's own `kx_node.cpp`/`kx_node.h`.
3. `esp/build.sh --show-diff` prints a readable unified diff locally, from the user's own checkout.

Verified at release: regenerating the sketch this way reproduces the validated sketch byte for byte. A
fresh compile of the release sources gives `KestrelBridge.bin` sha256 `5133f810...ccdb`, not the validated
`f1a96a1c...bdd4`. The validated image was read back from the board's app0 partition and compared:
same length (949,936 bytes), and every byte identical except the app descriptor's embedded ELF SHA-256
(offsets 0xb0-0xcf) and the image checksum and appended digest (last 33 bytes). The ESP32-S3 build is
therefore not bit-reproducible, but its code and data are (`scripts/esp_image_compare.py`; checked from
a fresh clone of the release with the same `esp/secrets.env`, since the SoftAP password is compiled in).

This is a conservative engineering choice, not a legal opinion. The `ed` script still encodes, by line
number, where upstream code is kept or replaced, and the fork's comments describe upstream behavior. If
Arduino later publishes a license for the repository, the fork could be redistributed as ordinary source
under that license's terms. The history before the release commit contained a full copy of the modified
sketch; the public history was rewritten to remove it (docs/PUBLICATION_AUDIT.md).
